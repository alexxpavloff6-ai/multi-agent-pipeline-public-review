# RUN-025: первый закрытый полезный цикл и его влияние на состояние продукта

**Дата:** 25 июля 2026 года

**Статус:** доказательный рубеж основной ветки; RUN закрыт, проект завершён

**Источник истины:** ветка `main`, коммит
`f6b9e71191b8024aff780869cf1e2d8f582496e6`

**Основные внутренние источники:** `main:docs/164`, `main:docs/165`,
`main:docs/166`, `main:docs/168`, `main:docs/169`, решения D-MODEL-032–036.

## 1. Зачем этот результат важен

RUN-025 является первым закрытым полезным трёхролевым циклом этапа 4 плана
«качество прежде цены». В отличие от ранних проверок подключения и отдельных
попыток оболочек, он прошёл содержательную последовательность:

1. низовой слой подготовил доказательные модули;
2. принятые модули стали входом полного синтеза Claude Code + GLM-5.2;
3. Codex независимо оценил синтез по заранее заданным критериям;
4. непринятый модельный результат сохранился неизменяемым;
5. отдельная детерминированная финализация исправила измеренные недостатки;
6. пользователь принял итоговое задание и итоговый отчёт;
7. ядро закрыло RUN и проект через проверяемые переходы состояний.

Этот результат завершает прежнюю стадию «полезный цикл ещё не выполнен».
Одновременно он не разрешает объявить весь продукт R1 или доказать
преимущество многомодельной схемы.

## 2. Точная конфигурация и границы переноса

Проверенный путь включал:

- низовой исполнительский слой Hermes Agent + DeepSeek V4 Flash;
- Claude Code 2.1.206 + GLM-5.2 с `effort=high`;
- Codex как независимую критическую и финализирующую роль;
- детерминированное ядро как единственного владельца состояний, архивов,
  денежных ограничений и закрытия;
- ручное решение пользователя на содержательных и итоговом шлюзах.

На момент закрытия местно уже была установлена Claude Code 2.1.216. Результат
версии 2.1.206 не переносится на неё автоматически. Вывод также не переносится
на другое задание, профиль Hermes, модель, поставщика или пределы.

## 3. Принятый конечный граф

Итоговый RPT-025 содержит четыре принятых листовых задания:

| Задание | Назначение | Итог |
|---|---|---|
| TASK-048 | доказательная основа M1 | принято |
| TASK-049 | доказательная основа M2 | принято |
| TASK-051 | исправленная доказательная основа M3 | принято |
| TASK-056 | действующая операторская инструкция | принято |

Исторические задания и попытки с отказами сохранены, но не подменяют
принятый конечный граф. Для законной цепочки `superseded` ядро проверяет, что
она заканчивается принятым листовым заданием того же RUN.

## 4. Что показал низовой слой

DeepSeek V4 Flash успешно подготовил M1 и M2. Первоначальный M3 потребовал
узкой детерминированной правки одного утверждения. Это подтверждает, что
дешёвая быстрая модель может выполнять ограниченные доказательные модули в
Hermes, если задача не передаёт ей работу оркестратора.

Однако один цикл не подтверждает безошибочность исполнителя. Измеренный отказ
M3 сохраняет правило:

- модули должны быть ограничены и проверяемы;
- содержательная приёмка обязательна;
- исправление не скрывает исходный результат;
- неделимая сложная задача или повторяемый содержательный отказ могут стать
  основанием для подъёма к более сильной модели внутри Hermes.

## 5. Что показал Claude Code + GLM-5.2

После транспортного ожидания и исправления объединения точного повтора Z.ai
вернул один полный ответ:

- HTTP 200;
- 25 990 входных токенов;
- 16 639 выходных токенов;
- 48 217 байт видимого текста;
- `stop_reason=end_turn`;
- договорная конечная метка присутствует.

Это прямое положительное наблюдение способности точной связки Claude Code
2.1.206 + GLM-5.2 завершить длинный синтез принятой доказательной основы.

Независимая оценка Codex одновременно установила, что результат выполнил
только 4 из 6 критериев:

- получился сильный доказательный обзор;
- не получилась воспроизводимая операторская инструкция;
- неверно истолкован смысл авторизации собственного вызова;
- не разрешён конфликт пределов 4096/32768;
- историческая версия Hermes 0.18.2 представлена как рабочая вместо 0.19.0.

Причина смешанная: часть ошибок относится к синтезу модели, часть — к
неполноте входного договора и отсутствию актуального снимка конфигурации.
Поэтому результат нельзя использовать ни как доказательство слабости GLM
вообще, ни как доказательство её достаточности без финальной редакторской
работы.

## 6. Роль Codex и честность финализации

Codex не переписал исходный ответ GLM задним числом. Он:

1. отклонил TASK-055 как готовый регламент;
2. сохранил исходный текст с прежней контрольной суммой;
3. в отдельном задании TASK-056 подготовил действующую операторскую
   инструкцию;
4. исправил смысл авторизации, версии и предел вывода;
5. добавил точные команды, ожидаемые состояния и действия при отказах;
6. передал результат пользователю, не принимая собственную работу.

Пользователь отдельно принял TASK-056 по контрольной сумме. Это подтверждает
рабочее разделение: модельный синтез является доказательством, независимая
критика может его отклонить, а окончательное решение остаётся у пользователя.

## 8. Учёт расхода

Сумма `0.155377777 USD` является смешанной учётной величиной:

- оценки DeepSeek по токенам;
- верхняя неизвестная оценка 0.02 USD для вызова без проверяемой квитанции;
- расчётный эквивалент Coding Plan PRO 0.1095976 USD, а не отдельное списание;
- нулевая стоимость детерминированных заданий восстановления и финализации.

Отдельный резерв GLM был превышен, но общий предел RUN не нарушен. Этот факт
сохранён в отчёте и не используется как основание ухудшить качество ответа.

## 9. Что доказано

1. Полезный трёхролевой цикл этапа 4 можно провести до закрытого RUN.
2. Ограниченные модули V4 Flash могут образовать принимаемую доказательную
   основу, сохраняя измеренные ошибки.
3. Claude Code 2.1.206 + GLM-5.2 способен вернуть длинный законченный синтез
   без усечения в проверенной конфигурации.
4. Независимая критика способна отклонить технически полный ответ без влияния
   цены.
5. Преемник может использовать сохранённый ответ без повторного модельного
   вызова.
6. Отдельная финализация Codex и пользовательская приёмка не меняют исходное
   доказательство модели.
7. Ядро способно построить отчёт по конечным принятым ветвям, учесть
   `superseded`-цепочки и идемпотентно закрыть RUN и проект.

## 10. Что не доказано

RUN-025 не доказывает:

- готовность переносимого выпуска R2;
- работу на чистом стороннем компьютере;
- пригодность Claude Code 2.1.216 по результату версии 2.1.206;
- безошибочность V4 Flash или GLM;
- получение готового итогового документа только силами GLM;
- универсальность схемы для иных доменов и задач;
- превосходство многомодельного конвейера над одной сильной связкой;
- завершение D-150.

## 11. Отношение к R1

RUN-025 даёт прямое доказательство уровня В3: один реальный полезный цикл
точной конфигурации завершён и принят. Но формальная R1 не должна считаться
принятой автоматически, потому что остаётся сверить полный набор договоров и
проверок спецификации 152, в том числе:

- единый Д24 и его связь со всем графом;
- полноту машинно проверяемого входного пакета Codex;
- общий манифест и матрицу покрытия основы;
- единый координатор целевого графа;
- версии переносимого профиля;
- полный набор `R1-TEST` и `R1-AC`;
- область, в которой финализация Codex является штатной частью результата.

Правильный следующий шаг — не новый модельный RUN, а детерминированная сверка
RUN-025 с каждым шлюзом R1. После неё пользователь может:

1. принять узкую R1 с перечисленными остаточными ограничениями;
2. закрыть только измеренные блокирующие пробелы и провести один преемник;
3. признать RUN-025 полезным этапом 4, но недостаточным для R1.

## 12. Отношение к гипотезе качества и D-150

RUN-025 поддерживает механизм многооболочечной гипотезы: разные роли нашли и
исправили ошибки друг друга, а итог оказался лучше непринятого синтеза GLM.
Но это наблюдение не доказывает причинного преимущества всей схемы: нет
сопоставимого результата одной сильной связки на том же запечатанном задании,
слепого оценивания и заранее утверждённого протокола сравнения.

D-150 остаётся отдельным следующим доказательным уровнем. Его можно начинать
только после формального решения о состоянии R1 и отдельного утверждения
протокола, задач, равных условий и независимого оценщика.

## 13. Изменение документального статуса

После RUN-025 должны быть сняты утверждения:

- «этап 4 не завершён»;
- «полезный трёхролевой цикл не выполнен»;
- «GLM не проверялась на длинном полном синтезе».

Должны сохраниться утверждения:

- «работа над продуктом продолжается»;
- «формальная R1 требует отдельной сверки и решения»;
- «R2 и D-150 не выполнены»;
- «синергия моделей остаётся гипотезой»;
- «открытый публикационный репозиторий не является лицензией или заявлением о
  промышленной готовности».

## 14. Итог

RUN-025 завершает этап 4 и переводит проект из состояния «архитектура с
разрозненными испытаниями» в состояние «один точный полезный цикл доказан, но
границы R1 ещё должны быть формально приняты». Следующая работа должна
сосредоточиться на сверке R1 и подготовке корректного D-150, а не на новой
серии проверок подключения или неограниченной технической шлифовке.

Документ не создаёт RUN, не разрешает модельный вызов и не меняет официальные
состояния основной ветки.
