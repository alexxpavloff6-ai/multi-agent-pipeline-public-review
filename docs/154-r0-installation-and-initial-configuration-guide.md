# Руководство по установке и первоначальной настройке прототипа R0

> **Примечание к публичной редакции.** Связи внутри комплекта 149–157 и внешние
> официальные либо научные источники сохранены. Ссылки на закрытые запуски,
> местные пути, внутреннюю память, код и материалы вне комплекта заменены
> текстовыми указателями; соответствующие закрытые файлы не опубликованы.

**Редакция:** 1.0

**Дата:** 24 июля 2026 года

**Состояние:** руководство для текущего исследовательского прототипа на
Windows; не является паспортом переносимого выпуска R2

**Фактическая основа:**
[описание существующей реализации](153-current-implementation-and-r1-gap-description.md)

**Будущая нормативная цель:**
[единая спецификация R1](152-r1-product-specification.md)

## 1. Назначение

Руководство позволяет:

1. развернуть точный снимок текущего прототипа R0 на компьютере Windows;
2. установить и отдельно проверить Python, Git, Codex App, Hermes Agent и
   Claude Code;
3. сохранить ключи моделей внутри настроек соответствующих оболочек, а не в
   репозитории;
4. выполнить бесплатную местную самопроверку детерминированного ядра;
5. понять, какие операции R0 уже выполняет, какие пока делаются вручную и что
   появится только в R1 и R2.

Руководство **не разрешает** создание нового проекта конвейера, RUN, задания,
резерва или модельного вызова. Успех установки означает только готовность
местной основы. Он не доказывает качество модели, работоспособность полной
трёхролевой цепочки или переносимость выпуска.

## 2. Честная граница R0, R1 и R2

| Уровень | Что означает | Что не следует утверждать |
|---|---|---|
| **R0 — сейчас** | Исследовательский прототип, проверенный на основном компьютере Windows. Есть ядро SQLite, договоры, архивы, проверки, ручная последовательность ролей и отдельные переходники оболочек | Нет единого установщика, официального выпуска, чистой установки на стороннем компьютере и полностью автоматического полезного цикла |
| **R1 — следующий рабочий рубеж** | Один полезный последовательный цикл: утверждённый план Д24, три ограниченных модуля Hermes, принятая совокупная основа, полный итог Claude Code, критика Codex и решение пользователя | R1 ещё не реализован целиком. Наличие отдельных программ R0 не равно прохождению R1 |
| **R2 — будущий переносимый выпуск** | Установка на чистом компьютере по паспорту выпуска Д25, закреплённые зависимости, безопасное подключение ключей, проверка обновления и отката, переносимые настройки и комплект поставки | Этот документ нельзя использовать как доказательство R2: испытания на чистом стороннем компьютере не было |

Подробный состав разрывов приведён в
[документе 153](153-current-implementation-and-r1-gap-description.md), а
требования будущего R1 — в [документе 152](152-r1-product-specification.md).

Устанавливать программы следует только из официальных источников:

- Git для Windows — [git-scm.com](https://git-scm.com/download/win);
- Codex App — текущая [официальная справка OpenAI](https://learn.chatgpt.com/docs/app);
- Hermes Agent — [официальная установка](https://hermes-agent.nousresearch.com/docs/getting-started/installation/)

- Docker Desktop, если нужен опытный контейнерный путь, —
  [официальная установка Docker](https://docs.docker.com/desktop/setup/install/windows-install/).

Установочные команды поставщиков со временем меняются. Перед выполнением
сверяйте их с текущей официальной страницей. Загрузка и немедленный запуск
удалённого сценария PowerShell удобны, но означают исполнение изменяемого
сетевого содержимого. Для контролируемой установки безопаснее сначала скачать
сценарий, проверить источник и контрольную сумму, просмотреть его, а затем
запустить локальную копию.

## 5. Правила безопасности до установки

1. Работать из обычной учётной записи Windows. Повышенные права использовать
   только для явно описанного системного действия.
2. Не помещать API-ключи, токены, пароли и файлы `.env` в проект, Git, чат,
   отчёты или снимки экрана.
3. Не копировать пользовательские каталоги `%USERPROFILE%\.claude`,
   `%USERPROFILE%\.hermes` или `%LOCALAPPDATA%\hermes\profiles` в репозиторий.
4. Перед изменением существующего файла настроек создавать его резервную
   копию. Не заменять весь JSON либо YAML, если требуется изменить несколько
   полей.
5. Не изменять обычный профиль самостоятельного Hermes ради конвейера.
6. Не считать текстовый запрет в задании средством изоляции. Ограничения
   обеспечивают профиль, процессная граница и ядро.
7. Не выполнять проверочный модельный запрос во время местной установки.

## 6. Получение точного снимка проекта

### 6.1. Почему обычная команда клонирования пока отсутствует

У текущего вложенного репозитория нет настроенного удалённого источника, тега
выпуска и паспорта Д25. Поэтому в R0 нельзя честно указывать общедоступную
команду `git clone` как официальный способ поставки.

Для текущего компьютера используется существующий рабочий каталог. Для
передачи на другой компьютер владелец проекта должен подготовить доверенный
пакет Git и отдельно сообщить:

- имя ветки;
- полный идентификатор коммита;
- SHA-256 пакета;
- перечень включённых и исключённых каталогов;
- отсутствие ключей и временных результатов.

Пример подготовки пакета владельцем проекта:

```powershell
git status --short
git rev-parse HEAD
git bundle create pipeline-r0.bundle <ИМЯ-ВЕТКИ>
Get-FileHash .\pipeline-r0.bundle -Algorithm SHA256
```

Пример развёртывания уже проверенного пакета:

```powershell
Get-FileHash .\pipeline-r0.bundle -Algorithm SHA256
git clone .\pipeline-r0.bundle "<КОРЕНЬ-ПРОЕКТА>\multi-agent-pipeline"
Set-Location "<КОРЕНЬ-ПРОЕКТА>\multi-agent-pipeline"
git checkout <ПОЛНЫЙ-ИДЕНТИФИКАТОР-КОММИТА>
git status --short
```

Ожидаемый результат последней команды — пустой вывод. Если контрольная сумма
не совпала, установка прекращается. Самостоятельно выбирать «похожий» коммит
нельзя.

### 6.2. Каталоги, которые не являются частью чистой установки

Не переносить **как текущее рабочее состояние** нового компьютера:

- незарегистрированные временные `runtime/` и `.pipeline` из прежних опытов;
- пользовательские ключи и профили оболочек;
- локальные рабочие деревья других веток;
- кэши Python, Node.js, Docker и оболочек.

Отслеживаемые Git исторические документы и обезличенные архивные доказательства
могут входить в точный снимок как доказательная история. Они остаются
архивными и не должны автоматически становиться текущим состоянием нового
экземпляра.

## 7. Установка Python и Git

### 7.1. Python

Для наиболее близкого воспроизведения R0 установить 64-разрядный Python
3.14.x. Точно проверенная версия — 3.14.5. После установки открыть новое окно
PowerShell:

```powershell
python --version
python -c "import sys; print(sys.executable); print(sys.maxsize > 2**32)"
```

Первое значение должно относиться к 3.14.x, последнее — быть `True`.

Базовая самопроверка ядра использует стандартную библиотеку Python. Для
расширенных путей текущего снимка дополнительно наблюдались:

```powershell
python -m pip install "PyYAML==6.0.3" "httpx==0.28.1"
python -c "import yaml, httpx; print(yaml.__version__, httpx.__version__)"
```

PyYAML нужен предварительной проверке нативного профиля Hermes; httpx —
опытному файловому посреднику и относящимся проверкам. В R0 пока нет единого
закреплённого файла зависимостей. Поэтому установленные версии следует
записать в акт настройки; это прямой пробел до R2.

### 7.2. Git

Установить Git for Windows и проверить:

```powershell
git --version
git -C "<КАТАЛОГ-ПРОЕКТА>" status --short
```

Не создавать удалённый источник и не отправлять проект во внешнюю службу без
отдельного решения владельца.

## 8. Первоначальная настройка Codex App

### 8.1. Установка

Установить Codex App способом, который на момент установки указан OpenAI.
Точная команда установщика намеренно не закреплена здесь: способ поставки
приложения может меняться. После входа открыть именно `<КАТАЛОГ-ПРОЕКТА>`.

### 8.2. Обязательная проверка проекта

До содержательной работы Codex должен прочитать:

1. `AGENTS.md`;
2. `README.md`;
3. `memory/CURRENT.md`;
4. `memory/NEXT_ACTIONS.md`;
5. только относящиеся к задаче решения и документы;
6. последнюю относящуюся запись `memory/dialogue/`.

Авторизация Codex принадлежит приложению OpenAI и не записывается в проект.
Модель, версия приложения и режим рассуждения должны фиксироваться как часть
конкретной связки, если начинается официальный RUN.

### 8.3. Честное ограничение R0

В R0 Codex является пользовательским входом, постановщиком, критиком и
составителем отчёта, но эти действия ещё не оформлены воспроизводимым паспортом
сеанса. В R1 должен появиться проверяемый входной пакет, паспорт сеанса и связь
критики с точной редакцией результата. Открытие папки в Codex App этого не
заменяет.

## 9. Первоначальная настройка Hermes Agent

### 9.1. Установка оболочки

Официальная справка называет нативную поддержку Windows ранней опытной
версией. Именно нативный Windows-путь использовался в текущем R0; переход на
WSL или другую среду меняет связку и требует отдельной проверки.

После установки открыть новое окно PowerShell:

```powershell
Get-Command hermes
hermes --version
```

На проверенном компьютере код расположен в
`%LOCALAPPDATA%\hermes\hermes-agent`, а программа использует собственный
Python 3.11.15. Этот Python не заменяет Python 3.14 проекта.

### 9.2. Обычный и проектный профили

Самостоятельный Hermes и конвейер должны иметь разные профили:

- обычный профиль остаётся под управлением пользователя;
- для конвейера создаётся отдельный профиль `pipeline`;
- конвейер не выполняет постоянную команду `hermes profile use pipeline`;
- профиль выбирается только в среде дочернего процесса;
- изменение обычной модели, навыков или памяти пользователя не должно быть
  побочным результатом запуска конвейера.

Официальная команда Hermes создаёт отдельный профиль относительно текущего
`HERMES_HOME`. Переходник R0 ожидает машинозависимый путь
`%LOCALAPPDATA%\hermes\profiles\pipeline`, поэтому для его воспроизведения
нужно временно, только в одном процессе PowerShell, задать основу профилей:

```powershell
$previousHermesHome = $env:HERMES_HOME
try {
    $env:HERMES_HOME = Join-Path $env:LOCALAPPDATA "hermes"
    hermes profile create pipeline --no-skills --no-alias
    hermes --profile=pipeline setup
    hermes profile show pipeline
}
finally {
    if ($null -eq $previousHermesHome) {
        Remove-Item Env:HERMES_HOME -ErrorAction SilentlyContinue
    }
    else {
        $env:HERMES_HOME = $previousHermesHome
    }
}
```

Команда `setup` может обращаться к сети и изменяет только профиль `pipeline`.
Её выполнять отдельно от бесплатной самопроверки, после получения ключа у
поставщика. Ключ вводится в интерфейс Hermes и остаётся в `.env` профиля; в
проект его не копируют. Ключ `--no-skills` создаёт пустой профиль и отключает
последующее автоматическое добавление встроенных навыков; `--no-alias` не
создаёт отдельную постоянную команду профиля. Само наличие этой ручной
машинозависимой процедуры является пробелом до R2.

Текущий переходник ожидает профиль по адресу
`%LOCALAPPDATA%\hermes\profiles\pipeline` и проверяет, не читая содержимое
ключа:

- `config.yaml` существует и не содержит полей секрета;
- `.env` существует, является обычным файлом и имеет допустимый размер;
- файл `.no-bundled-skills` существует;
- каталог `skills` существует и пуст;
- постоянный шлюз профиля не запущен;
- средства, MCP, память, повторы и запасные поставщики отключены;
- задан один ход и модель `deepseek-v4-flash`.

Образец профиля R0 нельзя копировать
вслепую: в нём есть машинозависимый рабочий каталог и устаревший комментарий о
владельце ключа. Исполняемый переходник использует собственный доступ Hermes,
как описано в проекте передачи
и реализации переходника.
Перед R1 образец должен быть исправлен и превращён в переносимый договор.

### 9.3. Граница безопасности Hermes

Профиль отделяет настройки, память, сеансы, навыки и ключи, но сам по себе не
является файловой песочницей. Нативный путь R0 запускает Hermes под Windows Job
Object, ограничивает время, память и дерево процессов, однако процесс имеет
прямой сетевой доступ к поставщику. Ограничение сети одним доменом не доказано.
Эта граница подробно зафиксирована в
документе 137.

## 10. Первоначальная настройка Claude Code

### 10.1. Установка оболочки

На Windows официальный путь Claude Code требует Git for Windows либо WSL.
Текущий R0 использует нативную установку Windows. После установки:

```powershell
Get-Command claude
claude --version
```

На основном компьютере наблюдалась версия 2.1.206. Обновлённая версия не
считается тождественной автоматически, потому что параметры командной строки и
поведение оболочки могут измениться.

### 10.2. Подключение GLM вне репозитория

Пользовательский файл Claude Code в Windows:

```text
%USERPROFILE%\.claude\settings.json
```

Перед изменением создать резервную копию. В существующий объект `env` добавить
либо обновить параметры из текущей официальной инструкции Z.ai. Не заменять
весь файл: в нём могут находиться разрешения, язык, тема и другие настройки.

Минимальные несекретные параметры проверенной схемы R0:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.z.ai/api/anthropic",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.2[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.2[1m]",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "1000000"
  }
}
```

`ANTHROPIC_AUTH_TOKEN` вводится только в пользовательской среде либо
пользовательском файле настроек согласно инструкции поставщика. Реальное
значение нельзя вставлять в документацию, договор задания или проект.

После запуска Claude Code команда `/status` должна показать пользовательский
источник настроек, адрес Z.ai и ожидаемую модель. Это проверка настроек, а не
разрешение отправить содержательный запрос.

### 10.3. Граница роли R0

В R0 существуют переходник, местный шлюз и опытный контейнерный путь. Однако:

- прямой переходник ограничивает вход примерно 16 КБ и выход 4096 токенами;
- полный Claude Code не стал рабочим координатором внутри AppContainer;
- контейнерный путь проверялся отдельно и не является обязательной частью
  базовой установки;
- достаточность полного входа и выхода для R1 ещё должна быть рассчитана;
- нет переносимого паспорта профиля Claude Code.

Поэтому установленный Claude Code с работающим `/status` ещё не доказывает
полную роль оркестратора R1.

## 11. Docker и системная изоляция

Docker Desktop **не нужен** для запуска самопроверки ядра и работы нативного
профиля Hermes. Он нужен только для сохранённых опытных путей изоляции Claude
Code и посредника.

Контейнерный путь требует закреплённых образов, внутренней сети без внешнего
маршрута и отдельной проверки отрицательных сетевых случаев. Наличие команды
`docker --version` не означает, что эта граница настроена. Подробности:

- AppContainer и его ограничение;
- контейнерная граница Claude Code;
- посреднический цикл.

Не создавать правила брандмауэра, профили AppContainer и контейнерные сети
просто ради базовой установки R0.

## 12. Бесплатная местная самопроверка

### 12.1. Уровень А — целостность снимка

```powershell
Set-Location "<КАТАЛОГ-ПРОЕКТА>"
git status --short
git rev-parse HEAD
python --version
git --version
```

Рабочее дерево должно быть чистым, а коммит — совпадать с паспортом полученного
снимка.

### 12.2. Уровень Б — наличие оболочек без вызова моделей

```powershell
claude --version
hermes --version
```

Эти команды не являются проверкой ключа или модели. Codex App проверяется
открытием нужного каталога и чтением `AGENTS.md` без запуска содержательной
задачи.

### 12.3. Уровень В — штатная самопроверка ядра

```powershell
python tools\pipeline_controller.py self-test
```

Самопроверка создаёт искусственное рабочее пространство во временном каталоге
Windows, проводит задание через техническую проверку и содержательную приёмку,
проверяет журнал событий и возвращает JSON с `"ok": true`. Она не вызывает
Hermes, Claude Code, Codex, модель или внешнюю сеть и не создаёт официальный
RUN проекта.

24 июля 2026 года команда успешно завершилась за 2 секунды. Получены:

- `ok=true`;
- состояние искусственного задания `accepted`;
- готовность передачи 100%;
- последовательность из 18 событий.

Временный путь и SHA-256 искусственных файлов меняются между запусками и не
должны сравниваться с приведённым наблюдением буквально.

### 12.4. Уровень Г — что не входит в самопроверку

Без отдельного решения не выполнять:

- `hermes setup`, `hermes model` и тестовый запрос модели;
- содержательный запрос Claude Code;
- создание RUN, задания, попытки и резерва;
- запуск посредника к DeepSeek или Z.ai;
- полную серию из сотен автоматических проверок;
- обновление оболочек и системных правил.

## 13. Первоначальный акт настройки R0

После уровней А–В оператор записывает **без секретов**:

| Поле | Что записать |
|---|---|
| Компьютер | условное имя, Windows, разрядность |
| Снимок проекта | ветка, полный коммит, SHA-256 пакета |
| Python | версия и полный путь |
| Git | версия |
| Codex App | версия или дата сборки, способ входа без токена |
| Hermes | версия, редакция, путь установки, наличие отдельного профиля `pipeline` |
| Claude Code | версия, источник пользовательских настроек, ожидаемый поставщик и модель без ключа |
| Дополнительные библиотеки | PyYAML и httpx с версиями |
| Docker | отсутствует либо версия; обязательным не считается |
| Самопроверка | дата, `ok`, число событий, код завершения |
| Отклонения | любое несовпадение с проверенной средой |

Этот акт пока оформляется вручную. В R2 он должен стать частью Д25 и
автоматической проверки поставки.

## 14. Что оператор R0 делает вручную

Даже после успешной установки вручную остаются:

1. выбор точной связки «модель + поставщик + оболочка + версия + настройки»;
2. постановка задачи и критериев Codex;
3. разделение полезной работы на ограниченные модули Hermes;
4. проверка и утверждение содержательной основы;
5. подготовка полного входа Claude Code;
6. отдельная критика результата Codex;
7. решение пользователя о принятии, остановке или новой редакции;
8. сопоставление фактического расхода без подмены качества ценой;
9. административное закрытие старых незавершённых запусков.

Ядро уже владеет состояниями, архивами, резервами, событиями и техническими
проверками. Модель или оболочка не должны менять их напрямую.

## 15. Типовые неполадки

| Признак | Проверить | Чего не делать |
|---|---|---|
| `python` не найден | открыть новое окно PowerShell; проверить путь установки | не менять договоры на случайный Python |
| `ModuleNotFoundError: yaml` | установить закреплённый PyYAML в Python проекта | не использовать Python из Hermes вместо Python проекта |
| `hermes` не найден | новый сеанс PowerShell; `%LOCALAPPDATA%\hermes\bin` в пользовательском `PATH` | не запускать файл из каталога исходного кода системным Python |
| профиль `pipeline` не проходит проверку | отдельный каталог, пустые навыки, остановленный шлюз, конфигурация без секрета | не менять обычный профиль и не читать `.env` из ядра |
| Claude Code сообщает повреждённый JSON | восстановить резервную копию и проверить запятые/скобки | не продолжать без пользовательских настроек и не затирать файл целиком |
| Claude показывает не GLM | источник настроек, адрес Z.ai, имя модели, версию Claude Code | не отправлять пробные запросы, пока причина не установлена |
| достигнута квота Z.ai | зафиксировать внешний отказ и остановиться | не повторять автоматически |
| самопроверка ядра неуспешна | сохранить полный вывод, версию Python, коммит, чистоту дерева | не переходить к оболочкам и моделям |
| Docker присутствует, но опыт не идёт | состояние службы, закреплённые образы, внутреннюю сеть | не ослаблять сеть ради успешного запуска |

## 16. Обновление и откат в R0

В R0 нет единого безопасного обновления всего продукта.

Перед обновлением любой части:

1. записать текущую версию и полный коммит;
2. сделать резервную копию пользовательской конфигурации оболочки без передачи
   её в проект;
3. обновить только одну часть;
4. повторить уровни А–В;
5. считать связку новой до отдельной содержательной проверки.

Откат проекта выполняется только к заранее сохранённому доверенному снимку.
Откат Hermes, Claude Code и Codex App зависит от способа их установки и пока не
объединён в Д25. Команды разрушительного отката Git в этом руководстве не
даются.

## 17. Критерии принятия установки R0

Установка R0 принимается только если одновременно:

- получен точный снимок с известным коммитом и чистым рабочим деревом;
- Python и Git доступны;
- `pipeline_controller.py self-test` возвращает `ok=true`;
- Codex App открывает проект и видит правила;
- Hermes и Claude Code сообщают версии без модельного запроса;
- обычный профиль Hermes не изменён;
- проектный профиль `pipeline` отделён от обычного;
- ни один секрет не попал в проект или журнал;
- все отклонения от проверенной среды записаны;
- оператор понимает, что полный полезный цикл и переносимость ещё не доказаны.

## 18. Что должно измениться для R1

До объявления R1 необходимо реализовать шесть пакетов из документа 153:

1. единый утверждённый план RUN Д24;
2. проверяемый вход, паспорт сеанса и критику Codex;
3. формальный полезный модуль Hermes;
4. манифест и матрицу принятой совокупной основы;
5. полный измеренный договор входа и выхода Claude Code;
6. один координатор точного графа и относящиеся местные проверки.

После этого нужен один принятый полезный цикл по спецификации 152. Новые
микропроверки подключения не заменяют этот результат.

## 19. Что должно измениться для R2

До объявления переносимого выпуска R2 необходимы:

1. паспорт выпуска Д25 с версиями, коммитами, SHA-256 и составом поставки;
2. единый закреплённый перечень зависимостей;
3. установщик либо воспроизводимый сценарий развёртывания;
4. машинозависимые настройки, создаваемые при установке, а не сохранённые в
   образце;
5. безопасная процедура подключения ключей без их появления в проекте;
6. проверка установки на чистом стороннем компьютере;
7. проверка обновления, отката и удаления;
8. переносимые профили трех оболочек;
9. включение подсистемы выбора моделей с прямыми источниками либо честное
   сохранение ручного выбора;
10. выпускные проверки R1 без обращения к настоящей модели, а затем отдельно
    разрешённый полезный приёмочный цикл.

Пока эти условия не выполнены, настоящее руководство остаётся руководством
исследовательского R0.

## 20. Следующий документальный этап

После пользовательской проверки этого руководства следует подготовить
**руководство оператора R0**: как открыть проект, восстановить состояние,
подготовить договоры, вручную провести роли, принять результат, остановить путь
при отказе и закрыть RUN. Оно также должно отделять действующие операции R0 от
будущего автоматического цикла R1 и выпускной эксплуатации R2.
